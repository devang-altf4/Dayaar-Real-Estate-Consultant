## 0. Operating rules

1. **Read `CALLING_MODULE_CONTEXT.md` in full before anything else.** It is the authoritative
   specification. This document does not replace it — it adds an audit, a deployment change, and
   an ordered work plan.
2. **Do not re-propose anything in Section 4 of the spec** (Twilio, Asterisk/SIP, GSM gateway,
   Exotel/CPaaS, Cloudflare R2, Cloudinary). Each was investigated and rejected for a documented
   reason. If you believe a premise has changed, say so explicitly and cite which reason changed.
   Do not silently design around them.
3. **One work package at a time. Stop and wait for approval between packages.**
4. **Report findings; do not fix silently.** If you discover a defect outside the current package,
   write it down and raise it. Do not opportunistically "fix" it.
5. **Evidence, not assertion.** Every claim about existing behaviour must cite `file:line`.
   Compilation is not acceptance. A passing typecheck is not proof a feature works.
6. **Never weaken existing security.** Section 3 lists invariants that are already implemented and
   must survive every change.
7. **Do not commit, push, deploy, seed, or touch production data** unless explicitly told to.
8. **Do not store secrets in the repo.** `CRM/.env` is currently untracked and there are no
   credentials in git history. Keep it that way.

### 1.2 Defects and gaps — these are the work

**D1 — There is no response-serialization layer at all. [CONFIRMED]**
Spec §9 requires access control enforced *in the response DTO*, not the UI. It is absent.
A search for `ClassSerializerInterceptor`, `@Exclude`, `@Expose`, `plainToInstance`, and `toJSON`
across `apps/api/src` returns **zero hits**.
`apps/api/src/common/interceptors/transform.interceptor.ts` only wraps payloads in
`{success, data, timestamp}` — it filters nothing.
`apps/api/src/common/guards/roles.guard.ts` is route-level only; everything else is ad-hoc scoping
inside services. **This is the single largest gap against the spec.**

**D2 — Recording storage is fiction. [CONFIRMED]**
`apps/api/src/modules/storage/storage.service.ts:14-17`:

```ts
if (providerType === 's3') {
  this.logger.log('S3 Storage Provider configured (Ready for AWS/R2)');
  this.provider = this.localProvider; // Fallback to local if S3 creds empty in dev
}
```

Setting `STORAGE_PROVIDER=s3` logs a success message and then uses **local disk**. There is no S3
SDK dependency anywhere in the workspace. Additionally, in
`apps/api/src/modules/storage/local-storage.provider.ts`:
- `getSignedUrl()` ignores `expiresInSeconds` entirely and returns a plain unsigned API route.
- `save` / `getStream` / `delete` use `path.join(basePath, objectKey)` with **no containment
  check** (path traversal by contract).

**D3 — `CallAttempt` does not match spec §8. [CONFIRMED]**
Current schema (`apps/api/src/database/schemas/call-attempt.schema.ts`) is missing every field the
Callyzer architecture needs: `commandId`, `origin`, `disposition`, `reason`, `notes`, `hotDetails`,
`followUpAt`, `dispositionAt`, `providerCallId`, `callType`, `connected`, `callDate`, `syncedAt`,
`recordingB2Key`, `recordingVpsPath`, `syncStatus`.
Renamed equivalents: spec `dialedAt` maps to code `startedAt`; spec `phoneNumber` maps to code
`phoneNumberDialed`.
`RecordingStatus` is `NONE|PENDING|AVAILABLE|FAILED` (`packages/shared/src/enums/call.enum.ts:43`)
but spec §8 requires `PENDING|ARCHIVED|NO_RECORDING|PURGED`.

**D4 — The webhook matching query has no supporting index. [CONFIRMED]**
Spec §8 mandates a compound index on `(employeeId, phoneNumber, dialedAt)` because it runs on
every webhook. Existing indexes are `(organizationId, leadId, startedAt)` and
`(organizationId, employeeId, startedAt)`; `phoneNumberDialed` is not indexed at all.

**D5 — Lead phone uniqueness is not enforced. [CONFIRMED]**
`apps/api/src/database/schemas/lead.schema.ts:116` declares `{ organizationId: 1, phone: 1 }`
**without `unique: true`**. Duplicate detection is therefore application-level and racy.

**D6 — Required config fields do not exist. [CONFIRMED]**
`Organization` has `maxUnsuccessfulAttempts` (default 4) and `dailyCallTarget` (default 300), but
**no `callingSeatLimit`** — spec §1 requires it, configurable, never hardcoded.
`User` has **no `callingEnabled`** flag — required by spec §1 and §8. Without it there is no way to
distinguish a paid calling seat from an ordinary CRM user, which is the core of the cost model.
Also note `User.email` is globally unique rather than org-scoped — a multi-tenancy wart, low
priority.

**D7 — `normalizeOutcome` misclassifies connected calls. [CONFIRMED]**
`apps/api/src/modules/calling/android-sim-calling.provider.ts` treats `durationSeconds > 0` as
`CONNECTED`. Spec §5.4 defines connected as **duration > 2 seconds**, matching Callyzer's own
`total_connected_calls` definition. As written, our numbers will not reconcile with their
dashboard.

**D8 — `CallCommand` expiry is 2 minutes; spec §6.2 requires ~60 seconds. [CONFIRMED]**
`android-sim-calling.provider.ts:33`. A phone coming back online can dial a stale lead.

**D9 — Missing dependencies. [CONFIRMED]**
No `@aws-sdk/client-s3`, no `bullmq`, no `firebase-admin`, no `@nestjs/throttler` anywhere in the
workspace. Storage, the rate-limited queue, FCM, and rate limiting all need to be added.

**D10 — Inherited claims you must verify in WP0. [UNVERIFIED]**
Check each and report status with `file:line`:
- `maxUnsuccessfulAttempts` exists but is never read; `>= 4` hardcoded in roughly four places.
- `dailyTarget: 300` hardcoded in `analytics.service.ts` (around line 269) despite the org field.
- `getDailyQueue` returns *lifetime* assigned leads, not a daily queue — "Lead 47 / 300" is not
  computable.
- CSV import is a textarea that splits on `,` with no quoted-field handling; import does one

- Analytics loads all of today's documents into Node and counts with `.filter()` instead of using

- Recording playback is broken: an `<audio src>` element cannot send an `Authorization` header.
- A "No Answer" button sets a lead to `NOT_PICKED_UP` directly, bypassing the attempts rule.
- "Hang Up" mutates local React state only.

## 2. Deployment change — Render, not Hostinger

**The spec assumes a Hostinger VPS. The demo will deploy to Render.** This is not cosmetic; it
breaks one part of the spec's storage design. Write the code so it runs on **both**, driven by
environment variables. Never hardcode either target.

### 2.1 What Render changes

| Spec assumption | Reality on Render | Required design |
|---|---|---|
| §7.1 secondary copy on "Hostinger VPS disk" | The filesystem is **ephemeral** — anything written at runtime is lost on restart or redeploy. Render Disks are paid, bind to a single instance, and block horizontal scaling. | Make the secondary tier **optional and pluggable**: `SECONDARY_STORAGE=none\|local`. Render demo uses `none`. VPS production uses `local`. |
| §7.2 step 5, "verify both succeeded" before deleting from Callyzer | With one tier there is no "both". | Gate on **every _enabled_ tier verified**. The invariant is unchanged and absolute: **never call Callyzer's delete endpoint until our primary copy is verified by reading it back** (HEAD plus byte-size match). Do not weaken this to make a demo work. |
| §5.5 nightly reconciliation, §7.3 retention job | Free instances sleep after inactivity; in-process cron will not fire reliably. | Implement every scheduled job as an **idempotent, independently-invocable unit** — callable by `@nestjs/schedule`, by a Render Cron Job, or manually via an admin endpoint guarded by a shared secret. No job logic may live only inside a timer callback. |
| VPS plus nginx plus certbot for the webhook | Render provides a public HTTPS URL with managed TLS. | This is *easier* on Render. Register the Render URL in Callyzer. Still authenticate the webhook — see below. |
| §5.5 BullMQ rate-limited queue | Redis is a separate paid add-on. | Put the queue behind an interface. If `REDIS_URL` is set, use BullMQ. Otherwise use an in-process single-concurrency queue. **The in-process path is correct only at one instance** — document it and pin Render to 1 instance while it is in use. |

### 2.2 Non-negotiable regardless of host

- **Production must fail closed.** If `NODE_ENV=production` and primary storage is not configured
  as B2/S3-compatible, the app must **refuse to boot** with a clear error. It must never silently
  fall back to local disk — that is exactly the bug in D2, and on Render it would mean recordings
  are deleted from Callyzer and then lost on the next deploy.
- **Authenticate the Callyzer webhook.** Spec §5.9 notes their delivery guarantees and retry
  behaviour are undocumented. Require a shared secret header or HMAC signature, store the raw
  payload in `CallyzerWebhookEvent` *before* processing, and make processing idempotent on
  `providerCallId`.

## 3. Security invariants — already implemented, must not regress

A prior hardening pass established these. Verify they still hold after every package:

- Device credentials are hashed and high-entropy; pairing needs a 6-digit code **and** a token;
  the claim is atomic and single-use with a 5-minute expiry.
- `DeviceAuthGuard` protects device routes; revoked devices have their token removed.
- Browser WebSocket connections use verified JWT identity; device sockets use deviceId/deviceToken;
  **rooms are derived server-side** — no client-supplied room joining.
- CORS uses configured origins, not wildcard-with-credentials.
- Production refuses fallback JWT secrets.
- The dev simulator is excluded unless `NODE_ENV != production` **and** `DEV_CALL_SIMULATOR=true`.
- All controller bodies run real runtime Zod validation; Mongo IDs are validated before conversion;
  lead search input is escaped before `RegExp` construction.
- Technical failures (`FAILED`, `CANCELLED`, device error, command expiry) must **never** consume a
  genuine customer contact attempt.

## 4. Decisions already made — implement as stated, do not redesign

These resolve ambiguities between the older build and the current spec. If you disagree, say so
before starting the package, not during it.

1. **Four-attempt rule: keep it**, driven by `Organization.maxUnsuccessfulAttempts`. It is absent
   from the new spec's data model but it is a real client rule and it is already built. Never
   hardcode `4`.
2. **Disposition lives on `CallAttempt`** per spec §8 (`HOT|WARM|COLD|NOT_INTERESTED|FOLLOW_UP`
   plus a **mandatory** `reason`). Derive and update `Lead.status` and `Lead.temperature` from it.
   Do not delete the existing `LeadStatus` enum or its server-side transition validation.
3. **Employees get no recording access at all** — not even their own calls (spec §9). Remove any
   employee playback path. Managers see team recordings; admins see everything.
4. **Secret QA verification is deferred, not deleted.** Park it behind
   `FEATURE_SECRET_VERIFICATION=false` (default off): routes return 404 when disabled, and it is
   removed from navigation. **Do not delete the module, the schema, or any data.**
5. **Web-initiated dialing is unconfirmed** (spec §13 blocker 5). Build the `CallAttempt` plus
   `commandId` model — needed either way — but put FCM dispatch behind `FEATURE_WEB_DIAL=false`.
   Android-initiated dialing needs no FCM at all.
6. **Device pairing and heartbeat stay** (still needed to target FCM and to identify the employee's
   handset). **Delete the device-side recording-upload path** — under Callyzer we never touch audio
   on-device (spec §6.4). Simplify `CallCommand` to the dial-command role with 60-second expiry.

## 5. Work packages

Execute in order. **Stop after each and wait for approval.**

### WP0 — Audit (read-only, no code)
Produce `CRM/AUDIT.md` in the format of spec §2.2 — for each area: **Status**
(Working / Partial / Broken / Absent), **Evidence** (`file:line`), **Recommendation**
(Keep / Refactor / Delete / Rebuild). Cover the full §2.1 checklist. Confirm or refute every
**[UNVERIFIED]** item in §1.2 D10 above, and re-verify my **[CONFIRMED]** items rather than
trusting them. Then **stop for review**.

### WP1 — Config and fail-closed boot
Add `Organization.callingSeatLimit`, `User.callingEnabled`, the retention window, and the feature
flags from §4. Remove every hardcoded limit found in WP0. Make production refuse to boot without
valid primary object storage.

### WP2 — Data model and indexes
Migrate `CallAttempt` to spec §8. Add the `(employeeId, phoneNumber, dialedAt)` compound index.
Add `CallyzerWebhookEvent` (raw, replayable). Add `Lead.consentSource` and `Lead.consentDate` per
spec §11. Make `(organizationId, phone)` unique on `Lead` — **detect and resolve existing
duplicates before creating the index** and provide a written migration procedure.

### WP3 — Serializer-layer RBAC  ← highest-value correctness work
Implement response-DTO enforcement per spec §9. Ship tests that assert a raw request with an
**employee** token returns **zero** recording fields (`recordingB2Key`, `recordingVpsPath`, signed
URLs) and no other employee's records. UI-level hiding is not acceptable.

### WP4 — StorageProvider
Real Backblaze B2 via `@aws-sdk/client-s3` pointed at the B2 S3 endpoint. Genuine signed URLs with
a short TTL. Path containment. Optional secondary tier per §2.1. Fail closed in production.

### WP5 — Callyzer client
Rate-limited queue (single concurrency, at least 2s spacing, exponential backoff on 429).
Authenticated webhook receiver writing raw payloads before processing. Nightly reconciliation via
`/call-log/history` as an independently-invocable job.

### WP6 — Matching engine
Spec §5.6 exactly: E.164 normalisation, `dialedAt ± 5 min`, closest-by-timestamp on collision with
a logged `MatchCollision`, `UNMATCHED` records retained in full with an admin view. **Never discard
a payload.**

### WP7 — Archival pipeline
Spec §7.2. Download, upload to B2, optional secondary copy, **verify**, and only then delete from
Callyzer. Retry with backoff; on failure leave the audio in place.

### WP8 — Retention and export
Spec §7.3. Default 9 months, configurable 6–12. Metadata never deleted. Purge gated on verified
export, never removes all copies in one action, every deletion audit-logged.

### WP9 — Web queue and disposition flow
High-throughput queue UI. Disposition **must never block on the recording arriving** (spec §5.7) —
mark and advance immediately, show a `recording pending` state. Enforce the ~3 minute minimum
re-dial gap.

### WP10 — Android companion app
**Blocked** until the handset recording test (spec §13 blocker 2) passes. Then spec §6: dial
intent, FCM handler, `PHONE_STATE` receiver, disposition screen, device-setup checklist.

### WP11 — Documentation and tests
Rewrite `docs/` to match what is actually implemented. Remove the S3 claim and the documented
`ACKNOWLEDGE_COMMAND` socket event if it remains unimplemented. Configure non-interactive ESLint.
